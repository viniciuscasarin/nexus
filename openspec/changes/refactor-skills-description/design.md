## Context

See proposal.md for motivation. The application currently stores and tracks skills with a simple `name` and `level` (e.g., beginner, advanced). The AI generation prompt currently uses `name` and assigns its own category, but it lacks deep context about what the skill means for the candidate. We are switching to a required `description` field for every skill.

## Goals / Non-Goals

**Goals:**
- Replace the `level` property with `description` across the system (DB, UI, Server Actions).
- Feed the new `description` into the AI context during tailored resume generation.
- Render the description (if generated by the AI) in the tailored resume view.

**Non-Goals:**
- We are not changing how experiences or degrees are modeled.
- We are not changing the overall flow of job application tracking or job analysis.

## Decisions

**1. Replacing `level` vs Adding `description`**
- *Rationale*: We are removing `level` entirely because it is mostly subjective and less useful for AI contextualization compared to a free-form `description` of how the skill was utilized. We are renaming/changing the field instead of keeping both to reduce form clutter.
- *Alternatives*: Keep both. Decided against this to keep the form focused on providing high-quality context rather than vague metrics.

**2. UI Implementation for Master Resume Form**
- *Rationale*: We will use a standard `<textarea>` or NextUI-equivalent `Textarea` for the description to give users enough room to type multiple sentences.

**3. AI Generation Prompt Changes**
- *Rationale*: We will explicitly instruct the AI to use the candidate's skill descriptions to understand their exact proficiency and application of the skill, and to synthesize a relevant, concise description for each skill in the generated resume.
- *Alternatives*: The AI could just output the raw description. We opted to have the AI generate/tailor the description just like it tailors experiences to ensure it fits the job description.

## Risks / Trade-offs

- **[Risk]** Existing data in the database will lose the `level` information during migration, and will have an empty `description`.
  - **Mitigation**: This is acceptable for a local development/study project. If needed, a migration script could map `level` to `description` ("Level: Advanced"), but we'll start with simply dropping the column and adding a required `description` with a default empty string (or handling the migration manually). Since it's local, `npx prisma db push` or resetting the DB might be sufficient.
